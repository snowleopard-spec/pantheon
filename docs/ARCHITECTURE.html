mini-dex

A non-technical guide to how the pipeline turns 8,000 SEC filings into 22 thematic stock baskets.

Companion to docs/MINIDEX_SPEC.md. Written for product managers and analysts who want the shape of the system without the code.

1. What this system does

mini-dex classifies US-listed technology and AI-adjacent companies into 22 thematic sub-indices — things like “fabless chip design,” “AI-native data-centre power,” and “frontier model labs.” For each theme it produces a weighted list of member companies, so that basket can be back-tested against real prices. The buckets are not mutually exclusive: a company like NVIDIA earns weight in several themes at once, in proportion to how much of its revenue plausibly comes from each. Output is a set of frozen CSV and Parquet files plus a manifest describing the run. It is a batch pipeline, refreshed perhaps annually, not a live service.

2. The end-to-end journey of one company

The clearest way to see the pipeline is to follow a single name through it. Take NVIDIA (ticker NVDA). Its trip through mini-dex has seven stops.

Stop 1 — Universe pull. The pipeline downloads the SEC’s master list of every US-registered public filer — roughly 8,000 companies with their tickers, names, and SIC industry codes. NVDA is in there, along with everything from banks to biotech to oil producers.

Stop 2 — Industry filter. A hand-curated list of SIC code ranges keeps only the tech-adjacent slice: semiconductors, computers, software, communications equipment, electrical apparatus, measuring instruments, telecom, data-centre REITs, and electric utilities. That trims the universe to about 1,376 candidates. NVDA (SIC 3674, semiconductors) survives. JPMorgan and Pfizer do not.

Stop 3 — Filing fetch and reading. For each candidate the pipeline pulls the most recent 10-K — the annual report every US public company is required to file with the SEC. It extracts “Item 1: Business,” the plain-English section where the company describes what it actually does and how it makes money. In parallel it pulls any structured revenue-by-segment data from XBRL (the machine-readable tags in the filing). For NVDA that gives the pipeline both the narrative (“we design GPUs and networking for AI training…”) and the segment table (“Data Center: $47.5B; Gaming: $10.4B; …”). When XBRL is thin or missing, an optional LLM step reads the 10-K text and pulls out any dollar-quantified splits the company mentions in prose.

Stop 4 — Embedding shortlist. Rather than ask an LLM to score NVDA against all 22 buckets, the pipeline first uses embeddings — a technique that turns a piece of text into a list of numbers so that texts about similar topics land near each other in that number space. Cosine similarity then measures how close two of those number lists are (0 = unrelated, 1 = identical topic). NVDA’s Item 1 gets embedded, each bucket’s definition gets embedded, and only buckets above a similarity cut-off (0.60) make NVDA’s shortlist — typically 1 to 6 buckets. NVDA lands on fabless chip design, AI accelerators, data-centre networking, and a couple of neighbours. It does not land on foundry or frontier model labs.

Stop 5 — LLM scoring. Only the shortlisted (company, bucket) pairs are sent to the Anthropic Message Batches API. The prompt shows the model NVDA’s Item 1 text, its segment table, and the definitions of just the buckets on its shortlist. The model returns, for each bucket, an estimated share of revenue (0 to 1), a confidence label, and a one-line rationale. Every company is scored twice, independently, so the QC step can see where the model disagrees with itself.

Stops 6 and 7 — QC and weighting. The QC step runs sanity checks: known anchor companies must score highly on their designated buckets (NVDA must land above 0.5 on fabless chip design); the two independent runs must roughly agree; borderline scores get flagged. Then the build step converts scores into weights three ways — equal-weight, score-weighted, and score × market-cap-weighted — normalised so each bucket sums to 1. NVDA ends up as a heavy weight in several silicon buckets and a lighter weight in a few software-adjacent ones, and the whole run is frozen to disk with a manifest recording every input version.

3. Data-flow diagram

4. The role of each Python file

Each module owns one job and talks to the others only through the database or the file cache. That is the whole reason the pipeline can be resumed, retried, and re-run stage by stage without redoing the expensive parts.

FileWhat it does, in one sentence
config.pyLoads API keys and paths from .env and exposes a single frozen settings object every other module reads.
db.pyCreates and opens the SQLite database and defines the tables (companies, filings, shortlist, scores, batches) plus the latest_scores view.
universe.pyStages 1–2: pulls the SEC master company list, tags each row with an industry code, and marks the tech-adjacent slice as candidates.
edgar.pyStage 3: for each candidate, downloads the latest 10-K, extracts the Item 1 business description, pulls segment revenue from the filing’s structured XBRL data, and records market cap.
llm_segments.pyOptional stage 3.5: for filings where XBRL segments are missing or useless, asks an LLM to extract quantified revenue splits from the 10-K text — refusing to guess if none are stated.
shortlist.pyStage 4: turns each Item 1 and each bucket definition into embeddings and keeps only the (company, bucket) pairs whose cosine similarity clears the threshold.
score.pyStage 5: builds the LLM prompt for every shortlisted pair, submits them via the Anthropic Message Batches API twice for independence, and parses the JSON responses into the scores table.
models.pyPydantic schemas that the LLM output must match — a defensive layer that rejects malformed rows before they touch the database.
qc.pyStage 6: produces a human-readable Markdown report of anchor-ticker sanity checks, run-to-run disagreements, borderline scores, and per-bucket member counts.
indices.pyStage 7: joins scores to market cap, computes three weight schemes per bucket (equal, score, score × cap), and freezes the run to outputs/<date>/ with a manifest.
cli.pyThin Typer dispatcher that maps minidex <stage> commands to the module functions above; contains no business logic.
scripts/performance.pyStandalone static back-test: reads a frozen weights file and a price history, holds weights constant from the freeze date, and prints cumulative return per bucket.

5. Major external dependencies

Service or libraryWhat it’s used for
SEC EDGAR (via edgartools)The master list of US public filers, each company’s SIC industry code, the latest 10-K annual report, and the machine-readable XBRL tags inside it that give segment revenue.
Anthropic Message Batches APIThe only paid input. Powers stage 5 scoring (revenue-fraction estimation per bucket) and the optional stage 3.5 segment extraction. Batches let us submit tens of thousands of prompts as one job at a discount.
HuggingFace BAAI/bge-large-en-v1.5Runs locally to turn text into embeddings for the stage 4 shortlist. Free, offline, deterministic. A smaller variant is available for faster iteration.
Yahoo Finance (via yfinance)Recent share prices for computing market cap in stage 3, and optional price history for the stand-alone back-test script.
SQLite (stdlib)A single local database file that stores everything each stage produces so the next stage can pick it up without re-running the previous one.

6. Configuration knobs (config.json)

Six tuning parameters live in a plain JSON file at the repo root (config.json) so they can be hand-edited without touching code or environment variables. Secrets (ANTHROPIC_API_KEY, SEC_USER_AGENT) stay in .env; only these tuning knobs live in the JSON. An environment variable (MINIDEX_<NAME_IN_CAPS>) beats the JSON value if set, and the JSON value beats the hardcoded default — so you get file-based defaults with per-run overrides for free.

Key Default What it controls
embedding_model BAAI/bge-large-en-v1.5 Which HuggingFace sentence-transformer to use for the stage 4 shortlist. The default is a 335 M-parameter model that loads to ~1.3 GB of RAM — excellent semantic matching. Swap to BAAI/bge-small-en-v1.5 (~130 MB) for RAM-constrained hosts; you'll typically want to lower similarity_threshold too since the smaller model produces slightly lower cosine scores.
similarity_threshold 0.60 The cosine-similarity cutoff for stage 4. Any (company, bucket) pair whose Item-1 vs. bucket-definition similarity exceeds this value goes into the shortlist to be scored by the LLM. Anchors are always included regardless. Lower values → more pairs scored → higher stage 5 cost but broader recall.
score_floor 0.10 Minimum LLM score required for a company to be included in a bucket's final composition (stage 7). Rows below the floor are dropped as immaterial exposure. Anchor tickers can override the floor via anchor_min_weight.
batch_model claude-haiku-4-5 Which Anthropic model powers stage 5 scoring (and the optional stage 3.5 segment fallback). Haiku is fast and cheap; you can swap to Sonnet if you want higher-quality scoring at ~4× the cost.
max_item1_chars 12000 Truncation length applied to each 10-K Item 1 text before it's sent to the LLM. ~12k characters is roughly 3k tokens, small enough to keep batch prompts cheap but large enough for most business descriptions. Raise for more context, lower for cheaper prompts.
anchor_min_weight 0.05 Minimum weight_cap_score that any anchor ticker receives in its bucket at stage 7. Below-floor anchors are force-included and hard-fixed at this weight; above-floor members scale down proportionally. Set to 0.0 to disable the floor entirely and use pure market-cap×score weighting.

7. Why the multi-stage design

A tempting shortcut would be to hand each company’s 10-K to an LLM once and ask “score this against all 22 buckets.” The pipeline is deliberately not built that way, and the biggest reason is cost.

With ~1,376 candidate companies and 22 buckets, that naive approach means roughly 30,000 (company, bucket) pairs to score — and each pair needs the full bucket definition injected into the prompt. The embedding shortlist collapses that: typical companies match only 1–6 buckets closely, so the LLM is asked about roughly 22× fewer pairs. A full pilot run scores something like 77 companies for around $25–$35 total. Without the shortlist, the same run would cost hundreds. Embeddings are essentially free to run locally, so pushing as much filtering as possible into that stage is the single biggest lever on budget.

Segment extraction is the second big lever, on accuracy rather than cost. If the LLM can see “Data Center: $47.5B, Gaming: $10.4B” alongside the narrative, its revenue fractions are anchored in filed numbers rather than adjectives. When XBRL is silent, the optional LLM segment step recovers what it can from the prose without fabricating.

The final reason is iteration. Because every stage writes its output to SQLite or disk, we can re-run the cheap stages — tweak the SIC filter, adjust the similarity threshold, re-embed with a different model — without paying to re-score everything. Only stage 5 costs money, and it is deliberately gated behind a confirmation prompt and a printed cost estimate. QC and build are pure recomputation; freezing a new index from an existing set of scores takes seconds.
